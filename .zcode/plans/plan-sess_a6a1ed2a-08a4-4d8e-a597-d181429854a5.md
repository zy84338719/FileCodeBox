# FileCodeBox 持续完善方案（第 2 轮）

基于上轮真实浏览器测试暴露的遗留缺陷 + 企业级能力补齐，本轮聚焦"让每个已暴露的问题真正可用"。

## 修复项（定向、有明确根因）

### 1. Swagger API 文档页修复（功能不可用 → 可用）
- **根因**：`Docs.vue:41` 从 `swagger-ui-dist/swagger-ui-es-bundle` 导入 `SwaggerUIStandalonePreset`，但该路径只导出 bundle default，不导出 standalone preset → `undefined` → `Cannot read properties of undefined (reading 'presets')`
- **修复**：改从 `swagger-ui-dist/swagger-ui-standalone-preset` 导入 standalone preset；简化 layout 配置避免依赖 standalone preset（用默认 layout 更稳健）。验证 `/openapi.json` 正常 + 浏览器渲染 Swagger UI。

### 2. 匿名取件 API 类型修复（400 → 正常）
- **根因**：`anonymous.ts:37` 的 `expire_value` 发 number，但 IDL `share_anonymous.thrift:16` 声明 `string`
- **修复**：前端 `anonymous.ts` 改用 FormData（与 `share.ts` 一致，强制 string），对齐 `expire_value`/`expire_style`/`max_pickup_count` 字段。浏览器验证 `/anonymous/generate` 不再 400。

### 3. Admin API 类型契约修复（消除潜在 400）
- **修复**：`admin.ts` 的 `getUsers` 参数 `page`/`page_size` 改为 required（对齐 IDL `required i32`），让 TS 强制调用方传参；清理响应字段名不匹配的死代码分支。

### 4. 主题切换体验优化（下拉 → 一键 cycle）
- **现状**：顶栏圆形按钮是下拉菜单（light/dark/auto 三选），`cycle()` 一键切换方法存在但未被使用
- **优化**：让顶栏 ThemeSwitcher 圆形按钮直接调用 `cycle()`（一键在 light/dark/auto 间循环），下拉菜单作为辅助。更符合"顶栏快速切换"的直觉。浏览器验证点击后 `html.dark` class 变化。

### 5. 数据库版本化迁移（企业级能力）
- **现状**：纯 GORM AutoMigrate，无版本控制/回滚
- **修复**：引入 golang-migrate，从当前 AutoMigrate 导出 baseline schema 作为 `00001_init.up.sql`；bootstrap 增加迁移步骤（配置开关，默认仍用 AutoMigrate 兼容旧部署）；Makefile 增加 `migrate-up/down/create` target。

## 验证方式
每项修复后用真实 Chrome (CDP) 重新跑对应场景验证：
- Swagger：API 文档页渲染出接口列表
- 匿名取件：generate 不再 400
- 主题切换：点击后 html class 变化
- 最后重跑全 E2E 套件（9 场景 + 5 页面）确认无回归

## 不做
- 不重写前端架构
- 不改 IDL 字段语义（保持向后兼容，只调整前端类型对齐）
- 不引入重型新依赖（golang-migrate 是唯一新增，是 Go 生态标准选择）
