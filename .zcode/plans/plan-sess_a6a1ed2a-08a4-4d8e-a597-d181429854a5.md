# FileCodeBox 企业级交付完善方案

## 核心发现（先说结论）

深入调查后发现：项目**表面功能完整，但存在几个致命的"接线缺失"问题**——代码写好了却没接上，导致核心能力在生产二进制里根本不生效。**企业级完善的第一步必须是修复这些致命缺口，否则所有上层优化都建立在"前端打不开"的基础上。**

### 🔴 致命问题（P0，必须先修）

1. **前端 SPA + 自定义 API 路由完全失效**
   - 真实入口 `cmd/server/bootstrap/bootstrap.go:248` 的 `customizedRegister()` 是**空函数**
   - 根目录 `router.go`（`package main` 死代码）里定义了前端静态服务、SPA fallback、`/openapi.json`、"我的分享管理 API"(5端点)、"用户通知 API"(4端点)——**全部未生效**
   - `bootstrap.go` 甚至已经注入了 `customHandler.SetNotifyService`/`SetShareService`，但**从未注册使用它们的路由**
   - **后果**：单二进制 / Docker 部署打不开前端页面；用户分享管理页、站内通知、Swagger UI 全部失效。这是"简单易用"和"企业级交付"的头号拦路虎。

2. **环境变量配置完全失效**
   - `docs/ENVIRONMENT_VARIABLES.md` 文档化了 `PORT`/`DATABASE_*`/`PRODUCTION` 等
   - 但 `bootstrap.go:67 InitConfig()` 从未调用 `v.AutomaticEnv()`/`v.BindEnv()`
   - **后果**：K8s/Docker 的 env 配置完全不生效，违反 12-factor；`--config` flag 也不被解析

3. **无全局 Recovery 中间件**——panic 导致进程崩溃（`internal/transport/http/middleware/recovery.go` 已写好但未注册）

## 实施计划（7 个阶段，每阶段独立可验证）

### 阶段 1：修复致命接线缺口（P0，让项目真正能用）
**目标**：单二进制 / Docker 部署即能打开前端、用上全部功能。

1. **激活自定义路由**：把 `router.go`（死代码）里的逻辑迁移到 `bootstrap.go` 的 `customizedRegister()`：
   - 前端 SPA 服务：`r.Static("/static", "./static")` + `NoRoute` SPA fallback（排除 `/api`、`/share`、`/user`、`/admin`、`/chunk`、`/anonymous`、`/notifies`、`/health`、`/metrics`）
   - `/openapi.json` → `customHandler.OpenAPISpec`
   - "我的分享管理 API"：`GET/POST /api/v1/user/shares/*`（5 端点，带 `UserAuth()`）
   - "用户通知 API"：`/api/v1/notifies/*`（4 端点，带 `UserAuth()`）
   - 用 `internal/pkg/middleware/auth.go` 的 `AuthMiddleware`（活跃包），不依赖 transport 死代码
2. **删除根目录死代码 `router.go`**——解决 `go build ./...` 的 "main undeclared" 报错
3. **激活全局中间件**：在 `h.Use(CORS())` 后追加 `h.Use(recovery)` + `h.Use(requestID)`（新写 request-id 中间件，与 `resp/response.go:33` 的 `X-Trace-Id` 对齐，写入 ctx）
4. **`go build ./...` 通过**，启动验证前端能打开

### 阶段 2：配置与环境变量（12-factor 合规）
**目标**：环境变量真正生效，敏感配置可外部化。

1. `bootstrap.go InitConfig()` 增加 viper env 绑定：
   - `v.SetEnvPrefix("FCB")` + `v.AutomaticEnv()` + `v.SetEnvKeyReplacer(strings.NewReplacer(".", "_"))`
   - 显式 `BindEnv` 关键项：`FCB_SERVER_PORT`→server.port、`FCB_DATABASE_DRIVER`→database.driver、`FCB_REDIS_HOST`→redis.host 等（对齐 `ENVIRONMENT_VARIABLES.md`）
   - 支持 `--config` flag（`flag.String`）覆盖默认 `configs/config.yaml`，并支持 `CONFIG_PATH` env
2. `conf.AppConfiguration` 补齐缺失字段：`Server.BaseURL`、`UI`（theme/background/page_explain 等）、`Observability`（metrics/tracing 开关与端点）
3. `jwt_secret` / presign `signingKey`：启动时若为默认值（`FileCodeBox2025JWT`/`filecodebox-dev-...`）且 `app.production=true`，则**拒绝启动并报警**（fail-fast），强制从 env 注入
4. 新增 `configs/config.example.yaml`（脱敏模板，移除硬编码 secret），更新 `config.prod.yaml`

### 阶段 3：生产可观测性
**目标**：Prometheus metrics + 结构化访问日志 + trace_id 全链路 + 深度健康探针。

1. **Metrics**（Prometheus）：
   - 新增 `internal/pkg/middleware/metrics.go`：HTTP requests total / latency histogram / in-flight gauge（按 method/path/status 打标）
   - 在 `customizedRegister` 注册 `/metrics`（promhttp）
   - `conf` 加 `observability.metrics.enabled/path` 开关
2. **访问日志 + trace_id 传播**：
   - 复用并激活 `transport/http/middleware/logger.go`（zap 结构化：method/path/status/ip/latency/trace_id）
   - request-id 中间件把 `X-Trace-Id` 写入 `context.Context` + `c.Set`，zap logger 带 `trace_id` field
3. **健康探针深化**：
   - `/health`（liveness）保持轻量；`/ready`（readiness）增加 DB ping + Redis ping 依赖检查（失败返回 503）
4. （可选 P1）**OTel 分布式追踪**：`otelhertz` 中间件 + OTLP exporter，复用 trace_id

### 阶段 4：质量与测试
**目标**：核心业务单测覆盖 + 数据库版本化迁移。

1. **补单测**（复用既有 testify + miniredis + sqlite 内存模式，遵循 `notify_test.go`/`anonymous_test.go`/`presign_test.go` 模式）：
   - `share`（Shape B：`db.SetDatabaseInstance(sqlite内存)` + hand-rolled mock storage/userService/notifySvc）——覆盖 ShareText/CreateShare/GetFileByCode/DeleteFileByCode/过期校验/取件次数
   - `user`（SetDatabaseInstance + AutoMigrate User/UserAPIKey）——注册/登录/JWT/API Key
   - `chunk`、`storage`（`t.TempDir()` 本地存储）
2. **数据库版本化迁移**（golang-migrate）：
   - 新增 `migrations/` 目录，从现有 AutoMigrate 导出初始 schema 作为 baseline
   - bootstrap 启动时优先跑 migrate，AutoMigrate 作为开发期兜底（可配置开关）
   - 文档说明迁移工作流
3. `make test` 全绿，覆盖率提升

### 阶段 5：安全加固
**目标**：限流持久化 + 敏感配置脱敏 + 密码哈希。

1. **限流 Redis 持久化**：`ratelimit.go` 增加 Redis-backed limiter（`go-redis` + 滑动窗口/令牌桶），内存版作为 fallback；多副本一致
2. **CORS/安全头**：激活可配置 CORS（`conf` 加 allowed_origins）；增加 `X-Content-Type-Options`/`X-Frame-Options`/`Strict-Transport-Security` 安全响应头中间件
3. **密码哈希**：确认 user/admin 密码用 bcrypt（`golang.org/x/crypto` 已在依赖）；若 plain/MD5 则迁移
4. **secret 不落盘**：`config.example.yaml` 不含任何真实 secret；Dockerfile/compose 通过 env 注入

### 阶段 6：K8s / 部署交付
**目标**：开箱即用的生产级部署清单。

1. **完善 `deploy/k8s/`**（在现有 base 上）：
   - Deployment：加 liveness(`/health`)/readiness(`/ready`)探针、resources(requests/limits)、env 从 Secret/ConfigMap 注入
   - 新增 `ConfigMap`（非敏感配置）、`Secret`（jwt_secret/db password 占位）
   - 新增 `Ingress`（带 TLS 占位）、`HPA`（CPU/内存）、`NetworkPolicy`
   - kustomize overlays：`overlays/prod`、`overlays/staging`
2. **docker-compose 生产版**：新增 `docker-compose.prod.yml`（backend + redis + 可选 mysql/postgres + nginx），对齐 `nginx.conf` 的 `filecodebox-go` upstream
3. **统一 Dockerfile**：根 `Dockerfile`（CGO sqlite + 非 root + healthcheck）作为生产标准；修正 `backend/Dockerfile` 的 8888 端口与 `--config` flag 问题；compose 改指根 Dockerfile
4. **README 部署章节**：单二进制 / Docker / Compose / K8s 四种方式一键部署说明

### 阶段 7：文档与交付收尾
1. 更新 `README.md`：架构图、快速起步（4 种部署）、配置/env 说明、可观测性、贡献指南
2. 更新 `backend/AGENTS.md`：新增中间件/observability/迁移约定
3. 清理过时文档（`.github/copilot-instructions.md` 标记或更新、`docs/` 冗余报告归档）
4. 新增 `CHANGELOG.md` / 完善 `docs/OPERATIONS.md`（运维：监控指标、日志、备份、升级）
5. 全量验证：`make check && make build`，Docker 构建测试，启动验证端到端（前端可开 + 核心 API + /metrics + /ready）

## 技术决策与依据

- **复用既有约定**：测试沿用 testify + miniredis + glebarez/sqlite 内存模式（无新依赖负担）；中间件沿用 Hertz `func(ctx, *app.RequestContext)` 签名；响应沿用 `{code,message,data,trace_id}` envelope
- **最小侵入**：阶段 1 只是把已有代码"接线"，不重写；后续阶段在 `internal/pkg/` 增量添加，不破坏 IDL 生成层
- **fail-fast 原则**：生产环境检测到默认 secret 直接拒绝启动，优于"静默使用弱密钥"
- **优先级**：阶段 1-2 是"让项目真正能用 + 可配置"，是其余一切的基础；阶段 3-7 是企业级增强

## 风险与缓解
| 风险 | 缓解 |
|---|---|
| 激活自定义路由可能与 IDL 生成路由冲突 | 路径前缀隔离（自定义走 `/api/v1`，IDL 走各自前缀）；启动时验证无重复注册 |
| migrate baseline 与现有库 schema 不一致 | baseline 仅用于新部署；已有库走 AutoMigrate 兜底 + 文档说明 |
| OTel/新依赖增加构建时间 | OTel 列为可选 P1；metrics 用轻量 promhttp |
| 限流改 Redis 影响单机部署 | Redis 不可用时降级内存版，配置开关 |
